# Управление тупым домом (Dumb Home)

Консольное приложение на C++ в стиле ООП, моделирующее управление
устройствами в квартире.

Название обыгрывает «умный дом»: сами устройства **«тупые»** — у каждого
только кнопка вкл/выкл и один числовой параметр (яркость, температура,
громкость, заряд). **«Умным»** является только центральный контроллер
`DumbHomeController`, который умеет считать энергопотребление, находить
самое активное устройство и строить маршрут уборки для робота-пылесоса.

## Возможности

- **Загрузка данных из файла** при запуске (формат `.txt`, разделитель `;`).
- **Сохранение изменений обратно в файл** по команде из меню.
- **Просмотр всех устройств** с полиморфным выводом состояния.
- **Фильтр по комнате** — показать только устройства выбранной комнаты.
- **Включение/выключение** отдельного устройства по имени.
- **Массовое включение** всех устройств в комнате одной командой.
- **Суммарное энергопотребление** включённых устройств (фишка №1).
- **Самое активное устройство** среди включённых (фишка №2).
- **Маршрут уборки** для робота-пылесоса с расчётом остатка заряда (фишка №3).
- **Корректная обработка ошибок файла:** пропуск пустых строк, сообщения
  о битых строках, неизвестных типах и неверных числах.

## Формат файла данных

Данные хранятся в текстовом файле `devices.txt` в кодировке **UTF-8**.
Разделитель полей — **точка с запятой** `;`.

### Структура строки

```
тип;имя;комната;состояние;доп_параметр
```

| Поле | Тип | Описание | Допустимые значения |
|------|-----|----------|---------------------|
| `тип` | строка | класс устройства | `Light`, `Thermostat`, `SmartSpeaker`, `VacuumCleaner` |
| `имя` | строка | имя устройства | любое |
| `комната` | строка | комната | любое |
| `состояние` | строка | вкл/выкл | `on`, `off` |
| `доп_параметр` | число | смысл зависит от типа | см. таблицу ниже |

### Смысл `доп_параметра` по типам

| Тип | Параметр | Диапазон |
|-----|----------|----------|
| `Light` | яркость | 0–100 |
| `Thermostat` | целевая температура | °C |
| `SmartSpeaker` | громкость | 0–100 |
| `VacuumCleaner` | заряд батареи | 0–100 |

### Пример `devices.txt`

```
Light;Люстра;Гостиная;on;80
Light;Ночник;Спальня;off;30
Thermostat;Термостат;Спальня;on;22.5
SmartSpeaker;Алиса;Гостиная;off;60
VacuumCleaner;Румба;Кухня;off;0
```

**Важно:** десятичный разделитель — **точка** (`.`) для совместимости с `std::stod`
и C-локалью. Если на вашей Windows-локали `std::stod` ожидает запятую,
в `main()` уже вызван `std::setlocale(LC_ALL, "C")`.

## Сборка и запуск

### Требования

- Компилятор с поддержкой **C++17** (g++ ≥ 7, clang++ ≥ 5, MSVC ≥ 2017).
- ОС: Windows / Linux / macOS.

### Сборка одной командой

Проект собран в **одном файле** `main.cpp`, поэтому компилируется тривиально.

**Linux / macOS / Git Bash:**

```bash
g++ -std=c++17 -Wall -Wextra -o dumbhome main.cpp
```

**Windows (MinGW):**

```cmd
g++ -std=c++17 -Wall -Wextra -o dumbhome.exe main.cpp
```

**Visual Studio (Developer Command Prompt):**

```cmd
cl /std:c++17 /EHsc /utf-8 main.cpp
```

### Запуск

```bash
./dumbhome devices.txt
```

Если имя файла не указано, используется `devices.txt` по умолчанию:

```bash
./dumbhome
```

### Особенности Windows

Для корректного отображения русских букв в `cmd.exe`/PowerShell в начало
`main()` добавлены:

```cpp
#ifdef _WIN32
    SetConsoleOutputCP(CP_UTF8);
    SetConsoleCP(CP_UTF8);
#endif
    std::setlocale(LC_ALL, "C");
```

Если всё равно видны «кракозябры» — установите в свойствах окна консоли
шрифт **Consolas** или **Lucida Console** и сохраните `devices.txt`
в **UTF-8 без BOM**.

## Архитектура и ООП

### Классы

| Класс | Роль | Тип |
|-------|------|-----|
| `IPrintable` | интерфейс «умеет печатать себя» | интерфейс |
| `Device` | базовое устройство | **абстрактный** |
| `Light` | лампа с яркостью | наследник |
| `Thermostat` | термостат с целевой температурой | наследник |
| `SmartSpeaker` | колонка с громкостью | наследник |
| `VacuumCleaner` | робот-пылесос с зарядом | наследник |
| `DumbHomeController` | управляет всеми устройствами | композиция |

### Реализация требований ООП

| № | Требование | Где реализовано |
|---|-----------|-----------------|
| 1 | Минимум 5 классов | 7 классов: `IPrintable`, `Device`, `Light`, `Thermostat`, `SmartSpeaker`, `VacuumCleaner`, `DumbHomeController` |
| 2 | Абстрактный класс | `Device` — методы `turnOn`, `turnOff`, `getType`, `getState`, `getParam`, `setParam` чисто виртуальные |
| 3 | Наследование (3+) | 4 наследника: `Light`, `Thermostat`, `SmartSpeaker`, `VacuumCleaner` |
| 4 | Полиморфизм | `printInfo()` вызывается через `Device*`, реальный метод определяется типом объекта |
| 5 | Инкапсуляция | Поля `protected`/`private`; доступ через геттеры и методы |
| 6 | Конструкторы | У всех классов конструкторы со списками инициализации |
| 7 | Виртуальный деструктор | `virtual ~Device() = default;` в базовом классе |
| 8 | Интерфейс | `IPrintable` с чисто виртуальным `printInfo()` |
| 9 | STL (2+) | `std::vector<std::unique_ptr<Device>>` и `std::map<std::string, std::vector<Device*>>` |
| 10 | Умные указатели | `std::unique_ptr<Device>` в `devices_`, `std::make_unique<>` при загрузке |
| 11 | «Фишка проекта» | 3 функции: `totalPower()`, `mostActiveDevice()`, `buildCleaningRoute()` |
| 12 | README.md | Этот файл |
| 13 | GitFlic | Проект загружен в репозиторий |
| 14 | Загрузка из файла | `DumbHomeController::loadFromFile()` |
| 15 | Сохранение в файл | `DumbHomeController::saveToFile()` |

### Ключевые механизмы

- **Полиморфизм.** В `DumbHomeController::showAll()` цикл идёт по
  `vector<unique_ptr<Device>>`, и вызов `d->printInfo()` динамически
  выбирает метод наследника.
- **Виртуальный деструктор.** `unique_ptr<Device>` корректно удаляет
  объекты наследников при `devices_.clear()`.
- **Композиция + агрегация.** `devices_` владеет устройствами
  (`unique_ptr`), `rooms_` хранит сырые указатели на те же объекты для
  быстрого поиска по комнате. Время жизни обеспечивает `devices_`.
- **Обработка ошибок файла.** Пустые строки пропускаются, битые строки
  логируются в `std::cerr` и не роняют программу, `std::stod` обёрнут
  в `try/catch`.

## «Фишка проекта»

Фишка — это **три собственные функции** в `DumbHomeController`,
которые превращают список устройств в осмысленную систему.

### 1. `totalPower()` — суммарное энергопотребление

Обходит все устройства, оставляет только **включённые** и применяет
**свою формулу мощности для каждого типа**:

| Тип | Формула | Обоснование |
|-----|---------|-------------|
| `Light` | `яркость × 1.0` Вт | чем ярче, тем больше потребление |
| `Thermostat` | `1500` Вт | нагреватель работает на фиксированной мощности |
| `SmartSpeaker` | `громкость × 0.5` Вт | усилитель нагружается пропорционально громкости |
| `VacuumCleaner` | `800` Вт | мотор всегда на полной |

**Пример вывода:** `Суммарное энергопотребление: 1610 Вт`.

### 2. `mostActiveDevice()` — самое активное устройство

Ищет среди **включённых** устройство с **максимальным параметром**.
Это алгоритм поиска максимума с фильтром по состоянию.

**Пример вывода:** `Самое активное: [Light] Люстра (Гостиная): горит, параметр=80`.

### 3. `buildCleaningRoute()` — маршрут уборки пылесоса

Собирает все комнаты из `std::map` (они автоматически отсортированы
по алфавиту) и для каждого пылесоса вызывает `VacuumCleaner::buildRoute()`,
который:

1. Печатает пошаговый маршрут по комнатам.
2. Считает **остаток заряда**: `battery - (кол-во комнат × 10%)`.

Доступ к методу наследника через базовый указатель реализован через
`dynamic_cast<const VacuumCleaner*>`.

**Пример вывода:**

```
Маршрут уборки для Румба:
   1. Гостиная
   2. Кухня
   3. Спальня
  Заряд на финише: 0%
```

## Отчёт о выполнении

### Что было сложно

1. **Согласование времени жизни объектов.** `devices_` владеет
   устройствами через `unique_ptr`, а `rooms_` хранит сырые указатели
   на те же объекты. Пришлось следить, чтобы `rooms_` не пережил
   `devices_` и не остался с висячими ссылками. Решение — очищать оба
   контейнера одновременно в `loadFromFile()`.

2. **Разные формулы энергопотребления.** Каждый тип устройства требует
   своей логики. Пришлось использовать `getType()` и цепочку `if/else`,
   а для доступа к методу наследника — `dynamic_cast`.

3. **Кодировка на Windows.** Первый запуск в `cmd.exe` дал «кракозябры»,
   потому что файл был в UTF-8, а консоль — в CP866. Решение:
   `SetConsoleOutputCP(CP_UTF8)` + `setlocale(LC_ALL, "C")`.

4. **Парсинг десятичных чисел.** `std::stod("22.5")` на русской локали
   возвращал `22`, потому что ожидал запятую. Помог `setlocale(LC_ALL, "C")`.

### Что получилось

- Полностью рабочее консольное приложение с меню из 9 пунктов.
- Корректная обработка ошибок файла: нет файла, пустая строка, битое
  число, неизвестный тип — ничего не роняет программу.
- Полиморфный вывод: один `printInfo()` работает для всех наследников.
- Три собственные функции-фишки, покрывающие анализ, поиск и симуляцию.
- Все 15 пунктов чек-листа выполнены.

### Что можно улучшить

- Добавить сценарии («Утро», «Ночь», «Ушёл из дома»), которые
  включают/выключают группу устройств одной командой.
- Реализовать отчёт по комнатам: сколько устройств, сколько включено,
  суммарная мощность.
- Добавить топ-N устройств по энергопотреблению.
- Перейти на формат JSON с библиотекой `nlohmann/json`.
